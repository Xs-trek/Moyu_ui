# Moyu v0.0.3 requirement memory

Status: frozen for v0.0.3; repository push authorized by the user after final static auth review.

This document records the user-approved v0.0.3 scope. OpenCode CLI adaptation, phone-side Chat,
provider API configuration and offline workspace branches are explicitly deferred to v0.0.4.

## V003-PAIR-001 — initialization emits pairing material

After `moyu -init` persists configuration and the background gateway becomes ready, the same
command starts a five-minute one-time pairing session and prints the relay plus pairing string in
`XXXXXXXX:PORT` form. `moyu -pair` regenerates a pairing session. No long-lived bearer token,
formal EasyTier network name or network secret is printed by this flow. Gateway or pairing startup
failure returns non-zero and does not claim pairing is ready.

## V003-CONV-001 — compact conversation chrome

The full conversation page reserves its height for the timeline and in-flow Composer. Its default
metadata chrome is one compact row containing the real platform icon, connection state, node and a
session-information button. Working directory, Profile, Model, session state and context usage are
collapsed by default and expand per session. Native-history cache notices live inside the scrolling
timeline rather than occupying a permanent grid row.

## V003-BRAND-001 — real platform marks

Claude Code and Codex CLI use bundled local Anthropic and OpenAI SVG marks, with text alternatives
provided by the containing component. The package makes no remote asset request. Provenance,
ownership and non-endorsement language must remain synchronized across source notices and APK
notices.

## V003-CONSOLE-001 — one composer owner

Console is a dashboard. It may show the active session summary, latest message preview, metadata,
Diff and a button into the full conversation. It must not render the full timeline, load-older
control, interrupt control or Composer. Those controls belong only to the full conversation page.

## V003-REL-001 — release candidate and freeze gate

The candidate identifies as UI/Android/backend `0.0.3`, Android `versionCode 3`, protocol version 1.
Before device handoff it must pass frontend build/static checks, backend typecheck/unit/integration
tests, Android unit tests, lint and arm64 APK identity/content/signature verification. The gate is
complete for v0.0.3; the user authorized the repository push after the final static auth review.
